1. 用 **Godot 4.7.2** 打开项目根目录的 `project.godot`

## 3. 完整游戏流程

```
开始（farm.tscn）
  │
  ├─ _ready：开场文字介绍 → 帷幕落下 → 开场对话 → 帷幕升起 → 提示"前往农田"
  │
  ├─ 走到农田触发点 → _Step1()    GameState.step = 1
  │     提示"按 E 收集成熟的胡萝卜"
  │
  ├─ 收满 2 个胡萝卜 → _Step2()   GameState.step = 2
  │     帷幕落下（不升起）→ 对话"怎么感觉风变大了？"
  │     同时 _start_storm()：雨/风/雾/树摇摆/积水 6 秒渐强
  │
  ├─ _Step3()                     GameState.step = 3
  │
  ├─ 进实验室（laboratory.tscn）
  │     若 GameState.step == 3 → _step_4()
  │       帷幕落下 → 玩家走到 Target1 → 对话 → Director 走 Target2 → Target3 → 对话
  │
  ├─ 回农场，收集 3 处「天气数据」（CollectionPoint）
  │     每处：走近 → 冒出 12 条半透明天气文字 → 按住 X 逐个吸到身上 → 该点消失
  │     集齐 3 处 → _step6()      GameState.step = 6
  │       任务面板："前往气象局提交数据"
  │       同时统计 GameState.carrots_required（当时剩余成熟胡萝卜数）
  │
  ├─ 去气象局找实习生（Intern）对话 → step = 7
  │     任务面板："回到农场提前采集成熟的胡萝卜，放入箱子"
  │     操作提示："互动：E"
  │
  ├─ 回农场收胡萝卜
  │     走近作物 → 描边高光 → 按住 E 出进度圈 → 收完变成掉落物（弹跳）
  │     走近掉落物 → 描边高光 → 按 E 拾取（**step >= 7 才能捡**）
  │
  └─ 走近箱子 → 箱子高光 + 开盖 → 按一次 E 全部倒入（抛物线飞入动效）
        放满 carrots_required → 淡出 + 结束文字 → 退出游戏
```

## 4. 核心系统详解

### 4.1 农作物 `Crop`

**文件**：`scripts/farm/crops/crop.gd`（`class_name Crop extends Area2D`）
**场景**：`scenes/fram/农作物/` 下 `胡萝卜.tscn`、`白萝卜.tscn`、`紫萝卜.tscn`

节点结构：

```
胡萝卜 (Area2D)          ← collision_layer=4(Detection)，被玩家射线检测
├ Sprite2D               ← crop_water 或 outline 材质
├ CollisionShape2D       ← 检测圆半径 12
├ StaticBody2D           ← collision_layer=1(World)，玩家物理碰撞
│ └ CollisionShape2D     ← 半径 6
└ ProgressRing           ← 37 帧进度圈，采集时显示
```

**关键属性**：
- `stage`：生长阶段（0~3），`is_mature()` = `stage >= regions.size()-1`
- `regions`：各阶段的图集区域
- `harvest_time`：采集耗时（默认 1 秒，按住 E 累积）
- `drop_region`：掉落物在物品图集的区域

**关键方法**：
- `on_ray_detected()`：玩家射线命中时调用（**当前高光实际由 Area2D 范围驱动，见下**）
- `is_mature()` / `is_highlighted()` / `can_harvest()`
- `harvest()`：立即采集（跳过进度条）

**高光机制**：
- 全局唯一高光：`static var _highlighted: Crop`
- `_update_highlight()` 每帧跑：玩家在范围内（`player_in_range`）且成熟的作物里，**离玩家最近的那个**亮
- **不依赖射线** —— 玩家射线从中心出发时起点可能落在 Area2D 内部，导致漏检

**采集流程**：
- `_process` → `_update_harvest(delta)`：按住 `interact` 累积进度 → 满 → `_complete_harvest()`
- `_complete_harvest()`：生成掉落物 → 发 `harvested` 信号 → `queue_free()`

**贴图裁剪**：`_get_padded_texture()` 从图集裁出 region 并四周补 1px 透明边，避免描边 shader 采样越界。

### 4.2 掉落物 `Drop`

**文件**：`scripts/farm/drop.gd` + `scenes/farm/drop.tscn`
**节点**：`Area2D` + `Sprite2D` + `CollisionShape2D`（半径 10）

- 纹理和 region 由 `Crop._spawn_drop()` 在实例化后注入
- 加入 `drop` 组
- 玩家进入范围 → 描边高光
- 按 E 拾取 → `GameState.carrots_held += 1` → `queue_free()`
- **限制**：`PICKUP_MIN_STEP = 7`，第 7 步之前按 E 无效

---

### 4.3 收集点 `CollectionPoint`

**文件**：`scripts/collection_point.gd` + `scenes/collection_point.tscn`

```
CollectionPoint (Node2D)
├ Sprite2D               ← 收集点图标
├ Area2D                 ← layer=4, mask=2
│ └ CollisionShape2D
├ AnimationPlayer        ← beat / hide 动画
└ WeatherData (Node2D)   ← 运行时生成 12 个 Label
```

- 玩家进入 → 显示 `WeatherData`（12 条半透明天气文字，绕中心排一圈）
- 玩家离开 → 隐藏
- **按住 X**（`Input.is_physical_key_pressed(KEY_X)`）→ 12 条文字依次抛物线飞向玩家 → 全部飞完 → `_play_hide()`
- 收完发 `collected` 信号（**只发一次**，`_collected` 标志保护）

⚠️ **坑**：`_collected` 和 `_absorbing` 的置位顺序很重要，`_absorbing` 必须在 `await _play_hide()` **之后**才置 false，否则收尾动画那 0.4 秒内再按 X 会重复跑完整个流程、重复发信号。

---

### 4.4 箱子 `Chest`

**文件**：`scripts/farm/house/chest/chest.gd` + `scenes/fram/house/chest/chest.tscn`

- 玩家进入 → 箱子开盖动画 + 描边高光
- 玩家离开 → 关盖 + 熄灭高光
- 带着胡萝卜按 **一次 E** → 身上全部倒入
  - 每个萝卜生成一个 `Sprite2D`，从玩家位置沿抛物线飞到箱子（`FLY_STAGGER=0.06`、`FLY_DURATION=0.45`、`FLY_ARC=20`）
  - 飞完才 `carrots_in_chest += count`
  - 达到 `carrots_required` → `_finish_game()`（帷幕落下 → 结束文字 → `quit()`）

### 4.5 天气系统

**场景**：`scenes/weather/weather_rain.tscn` + `scenes/weather/puddle.tscn`
**脚本**：`scripts/farm/farm.gd` 的「天气与积水」区域

`weather_rain.tscn` 结构（**注意没有 CanvasLayer**）：

```
WeatherRain (Node2D)
├ Rain        ← rain.tscn，内含 GPUParticles2D_Rain / GPUParticles2D_Splash
├ Wind        ← ColorRect，storm_wind.gdshader
├ Fog1        ← ColorRect，water_fog1.gdshader
└ Fog2        ← ColorRect，water_fog2.gdshader
```

**可调参数**（`farm.gd` 顶部 `@export`，检查器里能改）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `storm_duration` | 6.0 | 渐变总时长 |
| `rain_max_amount` | 2800 | 雨粒子数量 |
| `wind_max_opacity` | 0.25 | 风的不透明度 |
| `fog1_max_density` | 0.25 | Fog1 密度 |
| `fog2_min_alpha` | 5.0 | Fog2 alpha_p（越小越浓） |
| `fog2_max_strength` | 10.0 | Fog2 颗粒大小 |
| `puddle_threshold` | 0.55 | 积水阈值（越小水越多） |
| `puddle_opacity` | 0.22 | 积水不透明度 |

**`_start_storm()`**（6 秒并行 tween）：
- 雨：`amount_ratio` 0 → 1（**不是 amount！见坑**）
- 风：`opacity` 0 → 0.25
- 树：`wind_strength` 0 → 1（11 棵树，`tree.gdshader`）
- Fog1：`density` 0 → 0.25
- Fog2：`alpha_p` 100 → 5，`strength` 2 → 10
- 积水：`threshold` 1.0 → 0.55（**分 12 步改，不能每帧改**）

**`_stop_storm()`**：
- 雨停、风停、树停摇、雾散、**水波纹关掉**（`ripple_opacity=0` + 涟漪 SubViewport 停渲染）
- **积水保留不动**

⚠️ **巨坑**：
- **不要每帧改 `GPUParticles2D.amount`** —— 它每次改变都会重建粒子缓冲区，粒子全被重置，表现为「雨一直不出现，等渐变结束才突然冒出来」。要用 `amount_ratio`。
- **不要每帧改积水 `threshold`** —— `puddle.gd` 检测到参数变化会重建整张岸线距离场（遍历整张 mask 图像），每帧改会卡死。要分步（当前 12 步 × 0.5 秒）。
- **不要改 `Wind.speed`** —— 会造成「整个游戏在加速」的错觉。风变大靠 `opacity`。

### 4.7 玩家 `Player`

**文件**：`scripts/characters/rabbit.gd`（`class_name Player extends CharacterBody2D`）

**关键状态**（`PlayerState.current_state`）：
- `NORMAL`（0）：正常移动 + 射线检测
- `UNMOVE`（1）：不能移动
- `UNCONTROL`（2）：完全不能控制（剧情时）

**导航移动**：
```gdscript
await player._move_to_navigation_position(target_position)
```
- 内部设 `_is_navigating = true`，`_physics_process` 每帧驱动
- **移动方向不能 `.round()`** —— 取整后斜向长度变 1.414，速度忽快忽慢 + 方向跳变，表现为「鬼畜」

**采集动画**：
- `is_collection = 按住 E && has_harvestable_nearby()`
- 附近没有成熟作物时按 E 不会播采集动画

### 4.9 导航

**farm.tscn 和 laboratory.tscn 原本都没有 `NavigationRegion2D`**，所以两边的脚本 `_ready` 里都会**运行时生成**：

```gdscript
func _bake_navigation() -> void:
	var region := NavigationRegion2D.new()
	var polygon := NavigationPolygon.new()
	polygon.vertices = <四个角的 PackedVector2Array>
	polygon.add_polygon(PackedInt32Array([0, 1, 2, 3]))
	region.navigation_polygon = polygon
```

- farm：矩形 `(80,60) ~ (520,340)`
- laboratory：用 `Scene/Ground` 的 `get_used_rect()` × tile 尺寸

⚠️ **坑**：`make_polygons_from_outlines()` 在 4.x 上生成的多边形导航服务器不认，必须手动填 `vertices` + `add_polygon`。

## 5. 关键数据 `GameState`

`scripts/state/game_state.gd`：

```gdscript
var is_first_farm: bool = true    # 是否第一次进农场（控制开场流程）
var step: int = 0                 # 游戏主进度
var carrots_held: int = 0         # 玩家身上带着的萝卜数
var carrots_in_chest: int = 0     # 已放进箱子的萝卜数
var carrots_required: int = 0     # 这一关需要收集的总数
```

**`step` 的取值含义**：

| step | 含义 |
|---|---|
| 0 | 开场 |
| 1 | 提示收胡萝卜 |
| 2 | 风暴剧情 |
| 3 | 风暴后 |
| 4 | 实验室剧情 |
| 6 | 收集完 3 处天气数据，去气象局 |
| 7 | 气象局提交完，回农场收胡萝卜 |
| 8+ | 结束 |

## 7. 已知问题 / 坑一览

### 高优先级

1. **`farm.gd` 里有两处 `_remove_random_crops(15, 1)`**（约 L133 / L188）
   - 每次进场景会随机删 15 个作物，是**调试用**的
   - 正式发布前必须删掉，否则农田会凭空少一半作物

2. **`GameState.is_first_farm` 需要在离开第一次农场后置 false**
   - 目前 `farm.gd` L126 和 `black_transition.gd` L35 各有一处
   - 如果回农场时重播开场，检查这里

3. **`carrots_required` 的口径是「`_step6` 时剩余成熟胡萝卜数」**
   - 如果玩家在收集天气数据之前就收掉了一些，这个数字会偏小（回农场后能更快通关）
   - 想固定成「一开始的总数」，需要在 `_Step1` 时就统计一次

### 中优先级

4. **对话在 headless 下无法验证**
   - `_Step2`、`_step_4`、`intern_submit` 都依赖玩家点对话推进
   - 所有测试都是手动改 `GameState.step` 跳过对话的，对话本身没跑过

5. **导航停在离目标约 9px 的地方**
   - `NavigationAgent2D` 的 `agent_radius` 会导致可达区域收缩
   - 精确到点需要在导航结束后补一小段直线移动

6. **`_stop_storm()` 后 `weather_rain.visible = false`**
   - 如果之后还想保留残雾，要删掉这一行

7. **收集点的天气文字复用了收集点自己的图标纹理**（早期版本），后来改成 `Label` 文字——现在 `_setup_data()` 生成的是 Label，没有纹理依赖

### 低优先级

8. **`tools/` 目录有 7 个 `.gd.uid` 残留**，没有对应 `.gd`，可直接删

9. **`scenes/farm/` 和 `scenes/fram/` 两个目录并存**
   - `drop.tscn` 在 `scenes/farm/`，其他农场场景在 `scenes/fram/`
   - 是历史遗留，建议统一（但改路径要同步改所有引用）

## 10. 一句话总结

这个项目现在是一个**完整的短流程关卡**：开场 → 收两个胡萝卜触发风暴 → 实验室剧情 → 收集三处天气数据 → 气象局上交 → 回农场收胡萝卜 → 装进箱子 → 结束。

天气系统（雨/风/雾/树摇/积水）是视觉重点，所有参数集中在 `farm.gd` 顶部的 `@export` 区，直接调就行。最需要注意的三个坑是：**粒子 amount 不能每帧改**、**积水 threshold 不能每帧改**、**风速 speed 不要改**。
